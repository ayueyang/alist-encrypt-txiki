# 可选功能：明文锚点层（未实现，仅需求与方案记录）

> 状态：**需求探讨 / 可选功能**，非当前交付门槛。当前移植版本不因此改动任何代码。
> 依据全部来自上游原版代码实测（`work/api-harness/rule-model-probe.cjs`，2026-09-12），未做端到端验证处均已标注。

## 1. 需求背景

`encPath` 规则的匹配对象是**挂载点之下的路径**（如网盘挂载 `/会员`）。现状规则 `会员/.*` 之下，经代理创建的**第一层目录名也会被加密**（`/会员/电影` → 云端 `/会员/4nEdv`），导致：

- 在网盘官方客户端（如百度网盘 App）里，根目录看到的全是密文名，无法分辨哪个目录是自己挂的加密区。

**期望**：保留一个明文「锚点」文件夹——网盘根目录能看到 `电影` 这个明文名用于分辨，`会员/电影/` 之下全部密文（子目录名、文件名、内容）。

## 2. 上游原生即可表达的方案（不改代码）

利用规则匹配**不锚定**的特性，规则只写**叶子目录名**，不写挂载前缀：

```
encPath: ["电影/.*"]
```

上游代码实测行为（纯函数级）：

| 请求路径 | 匹配到的文本 | 转换结果 | 效果 |
|---|---|---|---|
| `/会员` | 无 | 原样 | 挂载层不受影响 |
| `/会员/电影` | 无（`电影` 后无 `/`） | 原样 | **锚点层保持明文名** ✅ |
| `/会员/电影/x.txt` | `电影/x.txt` | `/会员/电影/<enc x.txt>` | 仅文件名段加密 ✅ |
| `/会员/电影/sub/x.txt` | `电影/sub/x.txt` | `/会员/电影/<enc sub>/<enc x.txt>` | 子目录名+文件名都加密（需经代理创建） |
| `/会员/别的/电影/y.txt` | `电影/y.txt` | `/会员/别的/电影/<enc y.txt>` | 副作用①：任意树下的同名目录都命中 |

转换机制回顾：匹配文本按 `/` 拆段 → **丢掉第一段**（此处即 `电影` 本身）→ 其余每段加密。锚点目录名不出现在"被加密的段"里，因此永远保持明文；列表页里它也不会带 `orig_` 前缀（它是真明文，不是解不开的密文）。

### 限制与代价（原版逻辑内，需知悉）

1. **作用域是全局的**：任何树下的同名 `电影` 目录都会命中规则。挂载点专用时无影响；混用时需换更具体的写法（无解时只能接受）。
2. **`.*` 会吞掉锚点层以下所有层级**：子目录名也会被加密 ⇒ 子目录必须经代理创建；锚点层之下若存在**先于规则的明文子目录**，会出现与 R-30 相同的 mismatch（点开 404 / 下载损坏）。锚点层之下要"子目录名也保持明文"则超出上游能力（见 §3）。
3. **存量数据迁移**与 R-30 相同：规则生效前已存在的明文内容不会回溯加密，需经代理重传后删原件；迁移完成前旧文件从网盘官方入口取用。
4. **未做端到端验证**：目前仅纯函数级证据；若采用，应先在对照台（`work/api-harness/`）跑上传/列表/下载/WebDAV 全链路，再切换现场规则。

### 明确不可行的写法（实测）

- `会员/电影/*`：匹配文本包含 `电影` → 锚点层被一起加密（`/会员/JeIrJe3cm/...`）。
- `/.*`（带开头斜杠）：匹配文本以 `/` 开头，拆段丢掉空串后 `会员` 被加密 → `storage not found`。**规则永远不要以 `/` 开头**。
- `/会员/.*`：同上，绝对写法必然加密挂载名。

## 3. 未来版本可选功能建议（若做成产品化能力）

以下方案均遵循移植原则：**不修改上游业务逻辑**，只在配置保存边界（`normalizeAlistConfig` 所在层）或 UI 层做增强。

### 方案 A：锚点层规则向导（UI 层，推荐）

配置页增加"加密区"表单：填挂载名 + 锚点文件夹名，自动生成叶名规则 `锚点/.*`，并即时预览转换示例。
- 改动边界：仅前端/配置生成，运行时零改动。
- 风险：最低。用户不需要理解正则。

### 方案 B：规则语法糖 `挂载名/锚点/**`

允许写 `会员/电影/**`，保存边界将其**编译**为等价的上游正则（如 `电影/.*` 并校验唯一性），不碰运行时匹配代码。
- 改动边界：`normalizeAlistConfig` 同层的保存边界转换。
- 风险：低；需处理重名目录歧义（同名锚点多树命中时告警或要求唯一）。
- 收益：规则语义自文档化，且天然限制"锚点必在挂载点第一层"的书写意图。

### 方案 C：规则体检器（可与 A/B 叠加）

保存配置时静态检测并告警：
- 以 `/` 开头的绝对写法（必坏）；
- 规则中出现挂载名且会被加密的形状（`会员/电影/...`）；
- 规则不含 `/` 且无 `.*` 尾缀等可疑形状。
- 改动边界：保存边界校验，只告警不阻断（与上游兼容优先）。

### 方案 D（超出上游能力，需改运行时，谨慎）：锚点层之下"目录名明文"

若要"锚点之下子目录名也明文、仅文件名+内容加密"，上游 `convertRealPath` 的"逐段加密"机制不支持，需改运行时语义——**违背移植原则**，除非上游接受该特性，否则不建议做；可用 `encFolder=false` 的独立规则条目近似（目录名全明文，仅文件名加密）作为折中。
