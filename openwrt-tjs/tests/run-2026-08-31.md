# OpenWrt txiki.js 端到端测试记录

## T-01 Node 固定向量基线

- 目的：从干净上游基线得到算法、文件名和 Range 对照结果。
- 命令：`node dist/node-vectors.cjs`
- 实际输出：`ok=true`；AES-CTR、RC4、ChaCha20、MIX 的 SHA-256 分别为 `50d530bf...9261`、`71759b74...5e48`、`c50cda6e...72ff`、`37906b3b...51e1`。
- 结论：通过；1,000,065 字节数据、10 种分块边界、12 个 Range 偏移全部成立。
- 限制：该项在 Windows Node 运行，只作为对照，不算 OpenWrt 验收。
- 清理：无临时外部数据。

## T-02 txiki Worker 文件加载探针

- 目的：确认独立 `prga-worker.mjs` 能在 guest 中创建、收发消息并退出。
- 命令：`/usr/bin/tjs run /mnt/host/openwrt/alist-encrypt/openwrt-tjs/tests/worker-probe.mjs`
- 实际输出：Worker 路径为 `/mnt/host/openwrt/alist-encrypt/openwrt-tjs/dist/prga-worker.mjs`；返回 `msgId=worker-probe`、`i=7`、`j=24`。
- 结论：通过；pathname 加载方式有效，`terminate()` 后进程返回 shell。
- 限制：小向量只验证线程装载和消息协议，算法全量结果由 T-03 覆盖。
- 清理：Worker 已终止，无临时文件。

## T-03 OpenWrt 固定向量全矩阵

- 目的：在正式执行器中对比全部字节协议、分块和 Range 定位。
- 命令：`/usr/bin/tjs run /mnt/host/openwrt/alist-encrypt/openwrt-tjs/dist/openwrt-vectors.mjs`
- 实际输出：`ok=true`；四种密文 SHA-256、PBKDF2、MD5、SHA-256、文件名和目录派生密码均与 T-01 一致；12 个 Range 偏移全部为 `true`。
- 结论：通过；执行器为 OpenWrt guest 内 `/usr/bin/tjs`。
- 限制：ARM64 QEMU 中 1 MB 纯 JavaScript 测试耗时明显较长；该项不覆盖 HTTP 和 DAO。
- 清理：测试调用 `tjs.exit(0)`，常驻 Worker 不残留。

## T-04 日志脱敏固定用例

- 目的：防止密码、token、授权头、Cookie 和签名 URL 写入 OpenWrt 日志。
- 命令：`node tests/redaction-test.mjs`
- 实际输出：`json`、`headers`、`url`、`positional-login`、`config` 五项均输出 `REDACT_PASS`。
- 结论：宿主固定用例通过；平台边界能遮盖结构化字段和字符串形式的敏感值。
- 限制：guest `logd` 实际输出仍需在服务启动后验证。
- 清理：无临时文件。

## T-09 入站 Content-Length 头探针

- 目的：确认上传大小异常来自 txiki 请求头表面，而不是 `encNameRouter` 或 `FlowEnc`。
- 命令：`/usr/bin/tjs run /mnt/host/openwrt/alist-encrypt/openwrt-tjs/tests/inbound-header-probe.mjs`
- 实际输出：Fetch 客户端入站 `content-length="20,  20"`、`bodyLength=20`；原始 TCP 入站 `content-length="20"`、`bodyLength=20`。
- 结论：确认 C-20；txiki 自动长度与调用者显式长度合并为重复值，导致上游单值转换得到 `NaN`。
- 限制：探针只覆盖独立 txiki HTTP server，不代表真实 AList 上传已通过。
- 清理：探针关闭临时 5451 端口并退出，无 AList 写操作。

## P-01 OpenWrt 应用 APK 构建

- 目的：验证应用能以 OpenWrt 包安装，并声明现有 `txiki-js` 依赖。
- 命令：`sh openwrt-tjs/scripts/build-openwrt-package.sh <OpenWrt-ARM64-SDK>`
- 实际输出：生成 `alist-encrypt-tjs-0.3.0-r1.apk`；元数据依赖 `libc`、`txiki-js`，安装大小约 3.08 MB。
- 结论：包内容生成成功；首次结果的 `arch` 为 `aarch64_generic`，尚未达到架构无关包要求。
- 限制：这是中间产物；移动 `PKGARCH:=all` 到 `package.mk` 之后，必须重建并核对 `arch:noarch` 才能作为交付包。
- 清理：中间 APK 会被最终重建结果覆盖。

## T-05 完整服务首次 HTTP 冒烟

- 目的：验证挂载 bundle 启动后的静态页面、API 和透明代理。
- 命令：`/usr/bin/tjs run .../tests/http-smoke.mjs`
- 实际输出：第一项 `/public/index.html` 返回 HTTP 500；服务日志定位到 `request.signal.addEventListener`。
- 结论：失败；本次 guest 的服务端 Request 没有可用 AbortSignal，不能直接按 Node/浏览器对象假设调用。
- 限制：测试在第一项停止，登录和代理链路尚未执行。
- 清理：服务保留用于修复后复测；没有外部 AList 写操作。

## T-06 HTTP 冒烟第二轮与 Host 对照

- 目的：复测 AbortSignal 修复并验证透明代理。
- 命令：再次运行 `http-smoke.mjs`，随后在 guest 中分别对 relay 执行普通 Fetch 和显式 Host Fetch。
- 实际输出：静态 UI、`/index`、应用登录、鉴权 API 通过；透明代理为 HTTP 400。直接 relay 对照为普通 Fetch 200、手工 Host Fetch 400。
- 结论：部分通过；透明代理失败由 Fetch 的 Host 处理差异导致，出站头适配需过滤手工 Host。
- 限制：HEAD 未执行；AList 数据 API 和加密链路未进入。
- 清理：没有 AList 写操作。

## T-07 HTTP 冒烟第三轮与响应 framing

- 目的：复测 Host 修复并定位透明代理读取失败。
- 命令：运行 `http-smoke.mjs`，再分别打印 relay 与代理首页响应头。
- 实际输出：静态 UI、重定向、登录、鉴权继续通过；服务端已取回 AList 首页 3905 字节并改写为 4320 字节，但代理响应同时包含 `Content-Length` 与 `Transfer-Encoding: chunked`，客户端读取 body 报网络失败。
- 结论：部分通过；必须过滤 hop-by-hop 响应头并由 txiki HTTP 服务重新生成 framing。
- 限制：透明代理 body 尚未成功交付，HEAD 未进入。
- 清理：没有 AList 写操作。

## T-08 HTTP 冒烟第四轮与逐跳头修复

- 目的：复测 C-16，确认透明代理不再复制远端连接级 framing 头并能完整交付正文。
- 命令：重建 bundle 后，在 guest 中执行 `/usr/bin/tjs run /mnt/host/openwrt/alist-encrypt/openwrt-tjs/tests/http-smoke.mjs`。
- 实际输出：`static-ui` 200/3905 字节、`index-redirect` 302、`login` 200、`authenticated-api` 200、`alist-transparent-proxy` 200/4320 字节、`head` 405；脚本正常返回 shell。
- 结论：C-16 修复通过；透明代理正文已完整读取，Host 和 hop-by-hop 过滤没有破坏静态页与 `/enc-api`。
- 限制：现有脚本只确认 HEAD 有合法无正文响应，尚未与 AList 直连 HEAD 对照；JSON/form/binary/流式/多重重定向/Range/取消/Expect 仍由后续矩阵覆盖。
- 清理：服务继续以 PID `29728` 运行；没有 AList 写操作。

## T-10 C-21 WebDAV HTTP 方法解析器修复

- 目的：确认 WebDAV 所需的 `PROPFIND`、`MKCOL`、`COPY`、`MOVE` 已由新 txiki.js 运行时送达应用层，并且没有改变常见方法。
- 前置失败证据：已安装的 `txiki-js-26.6.0-r2` 对前四种方法返回 `HTTP/1.0 403 Forbidden`，应用没有收到请求；`PUT`、`GET`、`HEAD`、`DELETE` 能正常到达。仅设置 `LWS_WITH_HTTP_UNCOMMON_HEADERS=ON` 不能增加缺失的 method token，因此不是完整修复。
- 构建命令：`TXIKI_BUILD_ROOT=~/txiki-c21-build sh <工作区>/txiki-openwrt-rebuild-bundle/scripts/build-bundle.sh arm64 apk --with-binary`
- 安装命令：`apk add --allow-untrusted --network=no --force-non-repository /mnt/host/txiki-openwrt-rebuild-bundle/output/rebuilt/arm64-apk/txiki-js-26.6.0-r3.apk`
- 实测命令：`/usr/bin/tjs run /mnt/host/openwrt/alist-encrypt/openwrt-tjs/tests/webdav-method-probe.mjs`
- 实际输出：`ok=true`；`PROPFIND`、`MKCOL`、`COPY`、`MOVE`、`PUT`、`GET`、`HEAD`、`DELETE` 全部返回 `HTTP/1.1 200 OK`，且 `reportedMethod` 与发送方法逐项一致。
- 结论：C-21 的运行时方法解析阻塞通过。修复发生在 txiki vendored libwebsockets 的 token、lexer/parser 表和 txiki HTTP 映射；`alist-encrypt` 的 WebDAV 路由、XML、路径和加密业务逻辑未改写。
- 限制：该项只证明方法能到达应用层，不证明真实 AList WebDAV 的目录、上传、复制、移动、加密和清理链路；完整 E2E 由后续测试执行。
- 清理：方法探针使用临时回环端口并关闭服务；未写入 AList 数据。guest 保持 `txiki-js-r3` 和 alist-encrypt 服务运行。
