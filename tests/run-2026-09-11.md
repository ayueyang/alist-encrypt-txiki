# OpenWrt txiki.js 端到端测试记录（2026-09-11）

## 环境与原则

- 所有 OpenWrt 结论均由 guest 内 `/usr/bin/tjs` 执行。
- WSL Node、Windows Node 和宿主机浏览器只作为对照或访问工具，不计入 txiki 运行时证明。
- AList 测试使用 `/会员` 下动态隔离目录，凭据只通过当前进程环境或交互输入传递，本文件不保存账号密码、token、cookie 或完整签名 URL。
- 当前正式 QEMU 转发：`hostfwd=tcp:0.0.0.0:5344-:5344`，AList relay 为 guest 可达的 `10.0.2.2:5244`。

## R-01 固定向量与 Range

- 目的：确认 OpenWrt txiki.js 的 AES-CTR、RC4、ChaCha20、MIX、PBKDF2、摘要、文件名编码和目录派生密码与 Node 原版一致。
- 命令：

  ```sh
  /usr/bin/tjs run /mnt/host/openwrt/alist-encrypt/openwrt-tjs/dist/openwrt-vectors.mjs
  ```

- 实际输出：`ok=true`，数据长度 `1000065`；分块 `[1,7,15,16,17,63,64,65,1024,65535]`；偏移 `[0,1,7,15,16,17,63,64,65,999999,1000000,1000001]` 全部为 `true`。
- 固定摘要：AES-CTR `50d530bf...b0ec9261`；RC4 `71759b74...e9665e48`；ChaCha20 `c50cda6e...18f72ff`；MIX `37906b3b...53451e1`；PBKDF2 `a1db58f5a583ed980a6aed137929eda5`；MD5 `f39178e2ed2cac109e614582af2316ff`；SHA-256 `3fd9cca535eb1226579c46d722dc9c9edd9864617fc1ac294bb9b64afd2b1b88`。
- 结论：通过。字节协议和 Range 定位与 Node 基线一致。
- 限制：ARM64 QEMU 上纯 JavaScript 全量向量耗时较长；这不代表吞吐性能承诺。
- 清理：脚本退出并终止 Worker，无 AList 写操作。

## R-03 HTTP 能力矩阵

- 目的：覆盖 JSON、表单、二进制、流式上传/响应、302 和多次重定向、HEAD、Range、Content-Disposition，并记录取消和 Expect 限制。
- 命令：`/usr/bin/tjs run /mnt/host/openwrt/alist-encrypt/openwrt-tjs/dist/http-matrix.mjs`
- 实际输出摘要：

  ```text
  HTTP_MATRIX_PASS http-client-json status=200
  HTTP_MATRIX_PASS json status=200
  HTTP_MATRIX_PASS form content-type=application/x-www-form-urlencoded
  HTTP_MATRIX_PASS binary hex=0001027f80feff
  HTTP_MATRIX_PASS stream-upload body=stream-upload
  HTTP_MATRIX_PASS stream-response chunks=3
  HTTP_MATRIX_PASS redirect-302 status=302
  HTTP_MATRIX_PASS redirect-multiple status=200
  HTTP_MATRIX_PASS head status=204
  HTTP_MATRIX_PASS range status=206
  HTTP_MATRIX_PASS content-disposition attachment; filename*=UTF-8''matrix.txt
  HTTP_MATRIX_LIMITATION client-cancel upstream-cancelled=false
  ```

- 结论：正常 HTTP 矩阵通过。
- 限制：txiki v26.6.0 当前 ABI 没有可用的入站 `Request.signal`/Node close 事件；严格等待 `100 Continue` 的客户端不支持。
- 清理：临时 HTTP fixture 关闭。

- 结论：通过。r3 txiki 依赖修复生效。
- 限制：方法探针不等于 AList WebDAV 业务通过，业务由 R-06 覆盖。

## R-07 DAO 与重启恢复

- 目的：覆盖覆盖写、永久值、TTL、过期删除、空值、并发访问和进程重启后的持久化。
- 命令：`/usr/bin/tjs run /mnt/host/openwrt/alist-encrypt/openwrt-tjs/dist/dao-test.mjs`，并执行配置服务重启后读取探针。
- 实际输出结论：首次把 `ttl-live` 设为 60 秒后，因人工停留超过 TTL，重启读取按预期返回空值；这不是实现回归。将测试 live TTL 调整为 600 秒后，在同一测试窗口重新执行，`DAO_PASS` 覆盖写、live TTL、expired TTL、空值、并发、永久值和重启恢复全部通过，两个阶段退出码均为 0。
- 结论：通过。
- 限制：SQLite 文件语义已验证，未声称与 NeDB 的内部文件格式兼容。
- 清理：过期 key 已由 `clearExpire()` 清理；固定测试 key 保留在 SQLite 中供重复覆盖测试使用，不影响正式配置。

## R-12 运行证明

- guest：`OpenWrt 25.12.5 r33051-f5dae5ece4`，`armsr/armv8`，`aarch64_generic`。
- txiki：`/usr/bin/tjs --version` 输出 `v26.6.0`；guest 包清单含 `txiki-js` 和 `alist-encrypt-tjs`。
- 进程：最终重启后的 `PID 26026`；`readlink /proc/26026/exe` 输出 `/usr/bin/tjs`；命令行为 `/usr/bin/tjs run /usr/lib/alist-encrypt/server.mjs`。

- 结论：服务确实由 OpenWrt guest 内 `/usr/bin/tjs` 执行，不是宿主 Node 或 `qemu-aarch64` 用户态兼容运行。
