# R-33 桌面（Linux / Windows）txiki 直跑适配（2026-09-13 凌晨）

- **目标**：不经 OpenWrt guest，在桌面 Linux 与 Windows 用 txiki.js v26.6.0 直接运行同一份 `dist/server.mjs`。可行性结论与操作手册：`docs/desktop-txiki-runbook.md`。
- **可行性机理**：`dist/server.mjs` 为自包含 bundle（esbuild 打包，平台适配层内置），对 txiki 的依赖仅 `tjs:sqlite` + 标准 tjs API（`serve/stat/readFile/open/env/args/pid/exit/connect` + Worker）；桌面 txiki 与 guest txiki 同为 v26.6.0，API 表面一致。运行目录/配置/端口全部通过既有环境变量契约解决（`ALIST_ENCRYPT_HOME`/`ALIST_ENCRYPT_PROGRAM_DIR`/`ALIST_HOST` + `config.json.port`），**产品代码零改动即启动成功**。

## 发现并修复的平台缺陷：C-23 PRGA worker 路径（详见兼容文档 C-23）

- Windows 下 `new URL('./prga-worker.mjs', import.meta.url).pathname` 产生 `/C:/...`（URL 规范保留前导斜杠）→ txiki Worker 加载失败 → RC4/mix 的 PRGA worker 全部创建失败（主线程兜底保证功能正确，但失去多核加速）。
- 修复：`pathname.replace(/^\/(?=[A-Za-z]:\/)/, '')`——POSIX 行为逐字节不变，Windows 剥盘符前导斜杠。`PRGAThread.js` 本就是 txiki 适配改写文件（上游为 worker_threads）。
- 修复后 Windows 服务 stderr 无 worker 错误；8MB 大文件上传（B19）正常。

## 测试工具配套改动

- `api-suite.mjs` / `api-suite-run.mjs` 新增 `API_SKIP_WEBDAV=1`：跳过 C 组 9 项（记 SKIP）。**官方 Windows/macOS tjs 的 LWS 无 C-21 补丁，C01 的 fetch PROPFIND 会永久挂死**，桌面无补丁运行时必须设置。入口照旧兼容 guest/Node 两种运行时。

## txiki 二进制获取与 WebDAV 方法支持

- 官方 v26.6.0 release **只有 macOS/Windows 二进制，无 Linux** → Linux 走原生自编译（本机 WSL 2m39s 编完，`libffi-dev` 为唯一额外依赖），补丁树自带 C-21 → Linux 桌面版 WebDAV 完整可用。
- Windows 官方 zip 可用，但 **LWS 无 WebDAV 方法补丁：服务端 403、客户端 fetch PROPFIND 永久挂死**（与 OpenWrt prebuilt r1 同源，方法探针实测 GET/PUT/DELETE 过、PROPFIND 挂死）。桌面定位：AList HTTP 代理 + 管理页面可用；WebDAV 需自编译（指引见 desktop runbook §3.2，本机无 MSVC 工具链未实测）。
- 判定探针（30 秒自检）已写入 desktop runbook §3。

## 7. R-36：F-07（出站 `Origin` 头）判据取证与结案（2026-09-13 深夜）

### 7.1 要回答的两个问题

F-07 是 R-34 审查中唯一未结项：`utils/httpClient.js` 的 `createHeaders()` 在出站 Fetch 时跳过 `host`（C-15 已登记）之外还跳过 `origin`，而注释给的理由是「txiki.js 会给跨域 fetch 加上 Origin」。当时的挂起理由是**缺证据**，而非无法测：

- 问题①（运行时侧）：txiki 的 fetch 是否允许调用方决定出站 `Origin`？
- 问题②（对端侧）：目标端（AList / 存储 CDN）是否用 `Origin` 做鉴权或反盗链判定？

两个问题的答案合起来才能决定「恢复转发（对齐上游）」还是「保留过滤并登记」。

### 7.2 探针

| 编号 | 目的 | 工具 | 运行位置 |
|---|---|---|---|
| P1 | 运行时对 `Origin` 的处理（抛错 / 忽略 / 原样发出） | `work/api-harness/header-echo-server.py` + `origin-fetch-probe.mjs` | WSL 内桌面 tjs（`build-desktop/tjs`，v26.6.0） |
| P2 | 对端是否使用 `Origin` | `work/api-harness/cdn-origin-probe{,2,3}.sh` | WSL（宿主侧可出网；guest 侧不可达该 CDN） |

P2 取真实链路：AList `/api/fs/get` 取 `/会员` 下真实文件的直链，再用 WebDAV GET 的 **302 目标**作为 CDN 端点（`/p`、`/d` 在本挂载上被 AList 自代理、无 302，只有 WebDAV 通道会 302 到存储 CDN，这也正是 guest 侧 C04/C06 卡住的那一跳）。探针不打印、不落盘完整签名 URL。

### 7.3 结果

**P1 运行时行为**（回显服务器收到的请求头，节选）：

```text
调用方传 Origin=http://127.0.0.1:5344  → 对端收到 Origin=http://127.0.0.1      （端口被丢弃，调用方的值被忽略）
调用方传 host=evil.example             → 对端收到 Host=127.0.0.1 + host=127.0.0.1（同一头出现两次，均非 evil.example）
调用方完全不传 Origin                  → 对端收到 Origin=http://127.0.0.1      （运行时自行补上）
调用方传 Origin + referer              → referer 原样到达，Origin 仍为 http://127.0.0.1
四个用例均无抛错（PROBE ... OK status=200）
```

⇒ **结论①：txiki 的 fetch 不接受调用方给定的 `Origin`，一律改写为目标 origin，缺省时自行添加。** 上游 Node 版把入站 `Origin` 原样转发的形状，在 txiki 上**不可复现**。原注释的判断是对的；过滤只是把这个「本来就不可控的头」显式排除。

**P2 对端行为**（同一真实 302 目标 `yq01-cm01.baidupcs.com`，Range 0-1023）：

```text
curl UA，无 Origin                  → 403  94 B
浏览器 UA，无 Origin                → 403  94 B
浏览器 UA + Referer=pan.baidu.com   → 403  94 B
浏览器 UA + Origin=代理自身         → 403  94 B
浏览器 UA + Origin=第三方           → 403  94 B
HEAD（无 Range）                    → 403   0 B
响应体（各情形一致）：{"error_code":31362,"error_msg":"sign error","error_info":"","request_id":…}
```

⇒ **结论②：`Origin` 不参与该 CDN 的判定**（六种变因响应逐字节一致；403 由直链签名/请求方绑定决定，与请求头组合无关）。过滤与否在链路上**没有可观察差异**。

### 7.4 处置

- **不改码、不升包**：F-07 的本质是运行时边界（调用方无法决定出站 `Origin`），不是业务语义改动，也不是移植缺陷。登记为 **C-25**（`docs/openwrt-tjs-unsupported-and-replacements.md`），`porting-code-review.md` 的 F-07 与第 7、10 节同步结案。
- 由于不涉及 `node-proxy/src/` 变更，**dist 仍为 `78beaa11…`、应用包仍为 r9**，无需重编与再验收。
- 附带记录的运行时事实：txiki 生成的 `Origin` 省略端口（`http://127.0.0.1` 而非 `http://127.0.0.1:5399`），与 Fetch 规范对非默认端口的写法不同；对当前服务端转发用途无影响。

### 7.5 复现方式

```sh

python3 work/api-harness/header-echo-server.py 5399 &
~/alist-encrypt-arm-build/txiki.js/build-desktop/tjs run work/api-harness/origin-fetch-probe.mjs
# P2（WSL，需 AList 在 127.0.0.1:5244）

```
