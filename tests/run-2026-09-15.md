## 5. D01「跨目录 MOVE 500」的根因与归因

### 5.1 现象与排查路径

guest 套件中 `MOVE 复制目标/f → 可见目录/moved 样例.txt` 稳定 500。逐层排除：

1. **代理侧改写**：`encDavHandle` 对 COPY/MOVE 的源与目标分别做密文名翻译，代码路径与 C07（跨目录 COPY，201）完全相同 ⇒ 排除改写缺陷。
2. **AList 侧真实报错**（容器日志）：

```text
ERRO[2026-09-14 20:24:50] MOVE /dav/会员/_d01_…/1vhbEszH11441TNMF/5oCNpL+knz+pm4zTa4U6VFggU/5oCNpLU6mhqhx712zRug0.txt
     req: [https://pan.baidu.com/rest/2.0/xpan/file] ,errno: 12, refer to https://pan.baidu.com/union/doc/
github.com/alist-org/alist/v3/internal/op.Move   internal/op/fs.go:402
```

3. **驱动实现**（`drivers/baidu_netdisk/driver.go`，v3.60.0）：

```go
func (d *BaiduNetdisk) Move(ctx context.Context, srcObj, dstDir model.Obj) (model.Obj, error) {
    data := []base.Json{{"path": srcObj.GetPath(), "dest": dstDir.GetPath(), "newname": srcObj.GetName()}}
    _, err := d.manage("move", data)   // filemanager?opera=move，ondup="fail"，async="0"
    ...
}
```

即：**跨目录移动不向驱动传目标名（用源文件名落实体），且重名策略为 `ondup=fail`**；改名由 AList 的 WebDAV 层在移动后补做。

### 5.2 判别矩阵（绕开本代理，直连 AList `127.0.0.1:5244`，每例独立新文件）

| 形态 | 结果 |
|---|---|
| 跨目录 MOVE + 改名，目标目录**已有**同名 | **500** |
| 同一 MOVE，先删掉目标同名文件 | **201**，目标名正确为改名后的名字 |
| 跨目录 MOVE + 同名 | 201 |
| 跨目录 MOVE + 改名（明文名） | 201 |
| 跨目录 MOVE + 改名（含 `~` `+` 的密文风格名） | 201 |
| 同目录 MOVE + 改名 | 201 |

⇒ 唯一决定因素是「**目标目录是否已有同名（加密规则下即密文同名）**」。D01 的源文件是 `dav 样例.txt`，而 C 组已在 `可见目录` PUT 过同名文件，二者密文名相同 ⇒ 必然 `errno 12`。

### 5.3 处置

- **不是本适配层缺陷**：代理只做路径改写，直连 AList 复现同一结果。**不改代理代码**。
- 套件侧两处修正：① **D01** 改用不与目标目录重名的源文件（`跨目录样例.txt`）；② 新增 **D08** 把该语义固化为成因级用例——经代理与直连 AList 均断言 500，并在移除目标同名文件后断言同一 MOVE 恢复 2xx 且内容逐字节一致。
- 记录进 `docs/openwrt-tjs-unsupported-and-replacements.md`（AList/驱动侧限制）与 `docs/api-test-guide.md`。

## 6. D07：同目录换名 COPY 的 AList 侧 500

AList 自带 WebDAV 对「同目录 rename 语义的 COPY」返回 500（直连 AList 同样 500，与本代理无关）。用例只守住两条红线：不得退化为代理侧 **502**、不得出现明文名；状态码为 500 时记 `SKIP`（受限形态），若变成 2xx 则记 PASS（视为驱动能力提升）。

## 7. C-26：txiki Fetch 等待响应头的 15 秒上限

**现象**：guest 内并发两路 GET / PUT 偶发 `Network request failed: Timed out waiting server reply`，单路（暖场后）正常。

**源码定位**：

```c
/* deps/libwebsockets/lib/core/context.c:1176 */
context->timeout_secs = 15;
/* deps/libwebsockets/lib/roles/http/client/client-http.c:340 */
lws_set_timeout(wsi, PENDING_TIMEOUT_AWAITING_SERVER_RESPONSE, (int)wsi->a.context->timeout_secs);
```

txiki.js 的 `src/` 从不设置 `timeout_secs`，也未暴露给 JS ⇒ **15s 是硬上限**，且只约束「等待响应头」阶段（响应体流式传输不受影响）。

**影响面**：后端（百度 dlink 冷启动/限速）响应头超过 15s 的请求必然失败；并发请求排队后先超限的一路先失败。R-25 修复后 8MB 上传耗时 9.5–16.9s，本身即在该上限的临界带。

**处置**：不改码、不升包，登记为 **C-26**（`docs/openwrt-tjs-compatibility.md`）。套件把该形态记 `SKIP`（`SKIP::` 机制），状态码/内容不符仍判 `FAIL`；同时新增 **D03c**（并发两路 PROPFIND，不触达 CDN）独立证明代理的并发处理能力。
